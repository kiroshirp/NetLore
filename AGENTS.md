# NetLore — trabajo y comunicación

- Lee PROJECT-STATE.md al comenzar y contrasta el estado con Git antes de actuar. Actualízalo con cambios verificados y pendientes; no copies el historial completo.
- Responde en español, de forma breve: resultado, comprobación y limitación relevante. Evita repetir listas de cambios de turnos anteriores y no presentes trabajo parcial como cerrado.
- Distingue pruebas locales, comprobación visual y despliegue confirmado. No confundir paginación del navegador con paginación SQL ni CORS con autenticación.
- No publicar secretos, .env.local, .local ni registros privados. No modificar fichas reales para probar interfaces.
- Preserva el estilo oscuro/rosa y los tres idiomas. Ejecuta pruebas pertinentes y build antes de publicar interfaz.
- La API y el sitio se despliegan por separado. Conserva bindings, datos y controles de seguridad al desplegar el Worker. No declares que una cabecera está activa en GitHub Pages porque exista public/_headers.
